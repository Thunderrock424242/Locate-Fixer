# Locate Fixer 4.0 audit and implementation brief

Date: 2026-10-10. Baseline: `origin/1.21.1`, commit `6924335`.
Feature branch: `codex/locate-fixer-4-safety`.

## Confirmed issues

1. `AdaptiveSearchPlanner` skips small radii using successes and failures from
   unrelated origins. `SearchHistoryTracker` does not scope those hints to an
   origin. Historical distance is not evidence that a nearby area is empty.
2. Structure/biome/provider caches share coarse XZ origins; they do not establish
   nearest results at a different XYZ origin. Persistent index hits immediately
   return a recorded candidate without checking for closer undiscovered targets.
3. Ordinary structure output requests nine STRUCTURE_STARTS chunks to refine
   coordinates, introducing generation work unrelated to reporting the result.
4. Server-thread callbacks wait indefinitely in `result.get()`. The job manager
   is bounded, but an additional background executor has an unbounded queue.
   Reconfiguration creates additional workers while old workers drain.
5. Safe teleportation can carve a 3x3x3 air pocket. Global forced chunks are shared
   between overlapping operations, so one player's cleanup can unforce another's
   destination. Surface preference also loses underground destination context.
6. Teleporting depends on hidden grants and a global `/tp` mixin. Countdown and
   implementation chatter delay and complicate normal use.
7. Schematic scans and unrelated dimension travel are registered unconditionally.
   Generic command error correction touches give/summon/effect outside locate.
8. Server reload and shutdown do not clean every cache/history owner, and player
   disconnect is not an explicit cancellation boundary.

## Selected design

Keep the shared backend and public provider APIs. Retain intelligent nearby-first
planning and a bounded world index; hints can add stages or bounds but cannot prove
nearest results. Cache only compatible completed requests. Keep live world and
SavedData work on the server thread, with bounded cancellation-aware waits and
measured server-call duration. Do not interrupt a vanilla generation call midway.

Attach an explicit `teleport` child to vanilla locate argument nodes. Ordinary
locate reports native coordinates without preparing chunks. Teleport preparation
uses the existing loader tick lifecycle, unique temporary tickets, actual FULL
chunk readiness, bounded natural landing scans, final revalidation, and zero block
writes. Preserve orientation. Release resources on every terminal outcome.

Remove unrelated command registration and idle scanning while retaining deprecated
public classes as compatibility seams. Keep nearest/provider/diagnostic tools
optional. Preserve `locatefixer`, config keys, world data filename and schema
migration. Use Locate Fixer throughout branding, messages and assets.

## Issue 89

The [issue](https://github.com/Thunderrock424242/Locate-Fixer/issues/89) reports
Forge 47.4.20 / Minecraft 1.20.1 / Ixeris 4.6.5. Its attached crash report names
`locatefixer-3.1.0.jar` and an `InvalidInjectionException`: the `locateStructure`
target cannot be found and no refmap is loaded. Ixeris appears in the mouse event
stack, but that does not establish a thread ownership conflict. Validate current
Forge refmap packaging and startup; do not invent an Ixeris patch. The original
large modpack still needs live reproduction.

Follow-up on 2026-10-11: the published 3.1.0 Forge JAR declares a refmap that is
absent from its archive. The current 4.0 development candidate passed a minimal
Forge 47.4.20 / Ixeris 4.6.5 integrated-client world/locate probe. The old release
and original modpack were not launched. Exact evidence and repeat commands are in
[the Ixeris reproduction notes](ixeris-issue-89.md).

## Validation boundaries

Unit regressions cover planner/cache/index invariants, job ownership and cancellation,
command registration and read-only teleport landing/ticket bookkeeping. Build and
test all four loader/version targets and inspect production mixin metadata.
Dedicated-server smoke checks establish only the startup and command cases actually
exercised. Record actual server-call and tick-interval timing separately from search wall time. Gameplay, multiplayer,
custom dimension/mod combinations and comparative MSPT/CPU/memory benchmarks must
be reported as unverified unless measured in this run.

Completed implementation and exact evidence are recorded in `docs/4.0-validation.md`.
